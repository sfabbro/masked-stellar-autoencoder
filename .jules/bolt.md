## 2025-02-14 - Avoiding boolean indexing in PyTorch Loss Reductions
**Learning:** In PyTorch, using dynamic-shape boolean array indexing (like `input[mask]`) before mathematical reductions (`mean`, `sum`) triggers costly Device-to-Host (GPU to CPU) synchronizations, as the shape of the output tensor dynamically changes. This becomes a performance bottleneck inside training loops with custom loss functions containing mask conditions.
**Action:** Replace `input[mask]` with `.masked_fill_(~mask, 0.0)` applied on the full-shape tensors, followed by the normal reduction (e.g. `.sum() / mask.sum()`). For variables expected to have `NaN` or invalid mathematical states (e.g., in logarithms), the `masked_fill` prevents invalid operation errors. Always retain a `if reduction == "none":` branch applying the standard `input[mask]` fallback for 1D unreduced expectations.
## 2025-02-14 - Avoiding boolean indexing in PyTorch Loss Reductions
**Learning:** In PyTorch, using dynamic-shape boolean array indexing (like `input[mask]`) before mathematical reductions (`mean`, `sum`) triggers costly Device-to-Host (GPU to CPU) synchronizations, as the shape of the output tensor dynamically changes. This becomes a performance bottleneck inside training loops with custom loss functions containing mask conditions.
**Action:** Replace `input[mask]` with `.masked_fill_(~mask, 0.0)` applied on the full-shape tensors, followed by the normal reduction (e.g. `.sum() / mask.sum().clamp_min(1.0)`). For variables expected to have `NaN` or invalid mathematical states (e.g., in logarithms), the `masked_fill` prevents invalid operation errors. Always retain a `if reduction == "none":` branch applying the standard `input[mask]` fallback for 1D unreduced expectations. Also avoid branching `if mask.sum() == 0:` as it forces a CPU-GPU synchronization.
