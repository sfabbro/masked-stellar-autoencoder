# XP forward inversion and FlowEB diagnostic

This screen tests the existing MSA cohort (19,859 native fit and100,620 measurement-test stars), using all110 XP coefficients and reported errors. It does not update the pretrained encoder, present10M reconstruction rows, or acquire data. Epoch72 supplies only the existing audited scaler/input convention. Working software does not establish improved stellar prediction.

Four arms: direct110XP->FeH MLP; library ForwardInversionRegressor fitting FeH->110XP while treating the measured label as an exact code; the same forward architecture integrating the quoted FeH error under a flat prior; and FlowEB adding a learned1D intrinsicFeH prior. The flow axis is FeH, unlike the harness's scalar intrinsic-input flow. This is a multivariate-observable adaptation, not a reproduction of that toy linear experiment or its paper.

Policy:40epochs, batch256, AdamWlr.001/weightdecay0, seed42,64/64hidden layers. Each arm has3120updates and794360label presentations. Forward decoders, initial learned nuisance variance and epoch permutations match. The1D prior uses zukoNSF3transforms/32-32hidden/8bins. No new library dependency is required beyond the existing pinned2a99f4c.

XP errors are divided by the observed G-flux normalization and parent scale. Native off-diagonal XP covariance and common-G uncertainty are omitted explicitly. No noise is guessed for encoder latents. The forward Gaussian adds learned diagonal mismatch variance to quoted XP variance; this absorbs other stellar parameters and model error, not a physical error floor. FeH alone cannot explain Teff/logg/abundance/extinction variation. Reported FeH errors are random measurement uncertainties, not total calibrated truth errors. Test FeH values/errors never enter inference. All original source/error/128XP runtime gates must pass before production fitting.

For intrinsicFeH h, FlowEB integrates p(XPobs|h,sigmaXP) p(FeHobs|h,sigmaFeH) p_flow(h). Sum all110 XP log-likelihood terms before integration; only divide the final objective by110. The flat arm omits the prior factor, using an improper constant prior; absolute flat/FlowEB training objectives are not comparable normalized jointNLLs.

Integration uses64Gauss-Hermite nodes under a detached local-linear importance proposal, with the exact measurement/proposal density ratio. A measured-label-centered rule failed actual-input64/128convergence in retained smoke-v2; the adaptive implementation passes smoke-v3. Analytic Gaussian convolution and proper-prior jointGaussian/highSNR tests check both integration and importance correction. Fit-only first128row diagnostics compare32/64/128nodes;64/128meanNLL-perXP difference must be <=1%*max(1,abs(reference)). This is an aggregate convergence diagnostic, not proof of every nonlinear mode's integration accuracy.

Inference uses a common401point grid spanning fit-label min-minus1std to max-plus1std. Plugin/flat primary output is gridMLE; FlowEB primary is the prior-weighted finite-grid mean. All generative arms also save both estimators, posterior standard deviation and edge mass, allowing equal-estimator comparisons. GridMLE of the library's fitted decoder is the primary forward inversion, rather than its unbounded local Gauss-Newton optimizer; no frequentist covariance claim is made. Endpoint trapezoid weights and float64 likelihood accumulation are explicit. Prior shrinkage can hurt rare tails; grid truncation must be reported. No calibrated physicalPDF claim follows.
