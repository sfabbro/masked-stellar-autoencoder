# Nine-survey label contracts and ingestion gaps

26 October 2026. The versioned machine-readable contract is `configs/survey-label-registry-20261026-v1.json` (schema v1, revision 2026-10-26.1). This is a source/document audit: no downloads, jobs, model execution or training changes. It does not activate new sources. Only APOGEE DR17 and GALAH DR4 are verified in the current remediation core native-observation groups. A catalogue being public or an old file containing its name does not establish usable training labels.

## What is actually available to this pipeline

**APOGEE:** raw DR17 allStar and its corrected native projection are staged. `TEFF`, `LOGG`, `FE_H` and their errors are the atmospheric channel. `M_H` stays separate. Preserve flags, raw/calibrated variants, release and calibration dependencies; quoted precision is not total accuracy. Newer APOGEE analyses need a separate registry revision. SDSS DR20 carries the DR19 APOGEE ASPCAP files/analysis unchanged; it is not an independent analysis beyond DR19. Our staged native source remains DR17. [ASPCAP DR17 contract](https://www.sdss4.org/dr17/irspec/aspcap/), [DR20 carry-forward policy](https://sdss.org/dr20/mwm/data/).

**GALAH:** DR4 allstar is staged and supplies the other native channel. Current best practices explicitly say to ignore the erroneous `flag_fe_h`, require reliable stellar analysis and red-camera S/N, and apply named-element flags for abundances. The best-practices page supersedes conflicting older overview advice. The remediation projection repairs the old Fe/H flag selection. Retain both surveys on overlapping stars; do not overwrite one with the other. [Publisher recommendations](https://www.galah-survey.org/dr4/using_the_data/).

**DESI:** DR1 combined product and separate projected labels are staged. The archived `desi_labels_v1` manifest reports 2,976,271 selected unique stars; this is an earlier selected source view, not the current FIT count or a new all-row verification. RVSpecFit and FERRE/SP are separate, correlated pipelines. RVTAB `FEH` is a source-defined Fe/H estimate; `ALPHAFE` is not a universal alpha label. Preserve corrections, applicability, errors, quality and TARGETID-to-Gaia association. [Release](https://data.desi.lbl.gov/doc/releases/dr1/vac/mws/), [field definitions](https://desi-mws-dr1-datamodel.readthedocs.io/en/latest/mwsall.html).

**LAMOST:** the staged Li2025 DR10 CaT table and older Li high-resolution sample are limited products, not the full LASP catalogue. Their calibration methods and errors must survive ingestion. DR12 v2 LASP is a public candidate; this audit has no native full-survey ingestion receipt. LRS LASP and MRS/CNN cannot share an anonymous source index. [DR12 release notes](https://www.lamost.org/dr12/v2.0/doc/release_note), [staged CaT schema](https://cdsarc.cds.unistra.fr/ftp/J/ApJS/279/53/ReadMe).

## Requested sources with no verified native ingestion

**Gaia RVS DR3:** GSP-Spec provides spectroscopic temperatures, gravities, global metallicity and abundances. `mh_gspspec` is M/H; `fem_gspspec` is Fe I/M, not a direct Fe/H column. Adding Fe/M and M/H requires an explicit derived coordinate, error covariance and calibration policy. Retain flags and upper limits. Gaia RVS template parameters and XP/GSP-Phot are different products; the staged Gaia feature/VAC metadata does not certify a GSP-Spec label adapter. [Gaia archive schema](https://gea.esac.esa.int/archive/documentation/GDR3/Gaia_archive/chap_datamodel/sec_dm_astrophysical_parameter_tables/ssec_dm_astrophysical_parameters.html), [GSP-Spec analysis](https://doi.org/10.1051/0004-6361/202243750).

**Gaia-ESO:** the final public release is DR5.1, ESO catalogue 411 version 4 (published 2 July 2023). Its public release naming differs from internal iDR6 terminology; pin the actual DR5.1 archive file/digest before use. It supplies homogenised parameters and abundances; its different nodes, UVES/GIRAFFE setups, repeat spectra and cluster members need retained provenance and group splits. Exact native field/error mapping is deliberately unresolved in this registry, so it cannot silently enter FIT. [Final ESO DR5.1 catalogue](https://www.eso.org/qi/catalog/show/411), [release announcement](https://www.eso.org/sci/publications/announcements/sciann17584.html), [homogenisation paper](https://arxiv.org/abs/2304.07720).

**RAVE:** archived legacy derived filenames contain `rave`, but that does not establish raw DR6 flags, errors, Gaia association or pipeline lineage. Spectroscopic atmospheric m/H is a metallicity indicator, not direct Fe/H. A separate GAUGUIN iron product is a possible channel after field/flag verification. BDASP uses Gaia astrometric priors; seismic-calibrated gravities form another dependent product. These must not become independent duplicate labels. [DR6 methods](https://arxiv.org/abs/2002.04512).

**MaStar:** DR17 parameter VAC v2 is the documented preferred candidate. Keep the individual methods and master median distinct. Three Fe/H method sets use APOGEE calibration; methods share spectra, some use Gaia colour-magnitude priors, and repeat visits share stars. A master median is not an additional independent observation. No MaStar native ingestion receipt was found in the inspected inventory/configuration. [Parameter VAC](https://www.sdss4.org/dr17/mastar/mastar-stellar-parameters/).

**SDSS SpecObj:** this is a spectral identity/classification table, not an atmospheric-parameter estimator. The SDSS/SEGUE path requires a verified `specObjID` join to SSPP `sppParams` for Teff/logg/FeH and errors/quality. Repeated plate-MJD-fiber spectra cannot cross star splits. New BOSS/Astra estimators require separate entries; do not infer labels from class or redshift. [Official table/join guide](https://www.sdss4.org/dr17/tutorials/segue_sqlcookbook/).

## Required activation gates

1. Pin the exact file/release/pipeline and digest; verify actual native fields, units, Gaia identity joins and duplicate resolution. An absent entry in the old inventory is only *unverified ingestion*, not proof a file is absent from ARC today.
2. Keep one feature row per Gaia star and sparse observation records per source. Store source row, field definition/solar scale, flags, error-known mask, covariance availability, dependence group and raw/calibrated status. Missing errors stay unknown; missing targets stay unobserved.
3. Quantify surviving unique IDs and per-target/domain coverage after quality, features, ancestry and role exclusions. Catalogue totals never substitute for FIT counts. Keep inspected historical tests marked consumed; hold out linked stars/clusters/fields and shared reference families.
4. Fit relative survey offsets and error inflation only where overlaps support them. Source connectivity does not establish physical truth. Benchmark/seismic constraints require their own provenance and partial-target masks.
5. Reject generic M/H-to-Fe/H or alpha aliases. Age/distance posterior products stay separate teacher channels. This registry changes neither launch configuration nor the accepted pilot jobs.

## Verification scope

Evidence read: archived `label_registry_v2/inventory.json`, current `configs/stellar-catalog-sources.yaml`, native projection code, `remediation_source_v3` manifest, DESI projection and Li2025 collection manifests. Official documents above were checked on the audit date. The registry test checks the nine-source inventory, evidence paths, conservative activation allowlist, explicit incompatible metallicity fields, dependency/quality metadata and citation presence. It does not certify new raw catalogue rows, new crossmatches or astrophysical calibration.
